## Initial findings, all resolved on final rereview

- RCD-01 — Enforce the synchronous authority callback at runtime. TypeScript permits async functions in a void callback position; ignoring a Promise return silently skips authorization and can create an unobserved rejection. Require the documented synchronous result and reject/observe thenables. Qualify an accidentally async callback before model release.
- RCD-02 — Bind `contract.taskId` and `contract.revision` to the reviewed candidate's GAT task/revision. Public `createReviewPacket` validates the supplied contract/proposal association, not its association with the GAT revision. Test an old revision with otherwise recomputed valid hashes.
- RCD-03 — Rationale audit must include its specific reason and a unique invocation/call identity, separately from rationale ID. Reject whitespace-only reasons. Currently `requestId` is the rationale ID and reason is lost. Requested and terminal records must be correlatable; prepared does not mean delivered.
- RCD-04 — Count admitted native tool attempts including malformed arguments and denials before argument validation. Prevent repeated calls past the hard ceiling from invoking external audit or reader callbacks indefinitely; bound packet reads too. Every admitted requested read needs a prepared/denied/error disposition where audit remains available. Count and byte limits are enforced before disclosure, not inferred from model cooperation.
- RCD-05 — Sanitize host callback failures before model delivery. The current execute path rethrows raw audit/assertion errors and the finalizer passes bounded `isError` content through. Return a stable denial for those failures; qualify a host error containing a private sentinel. Do not claim the content finalizer controls registry-owned error/value/additional-context fields.
- RCD-06 — Project policy fields explicitly or validate a closed policy before spread. `...policy` after authoritative attempt/worker/reviewer fields currently permits unknown properties to replace those identities. Test injected policy identity keys.

Findings were sent directly to the prototype owner. They are contract-enforcement corrections inside the existing approved plugin scope, not a request for a larger review framework.

Final dispositions: RCD-01 rejects non-undefined synchronous assertion results and observes rejected thenables; RCD-02 checks exact contract task/revision; RCD-03 records a unique native root call ID for packet/evidence/rationale and a rationale ID/reason digest; RCD-04 reserves native attempts in the guard, caps interactive packet calls at 16, caps evidence/rationale attempts before callbacks and emits terminal aggregate-byte denial; RCD-05 emits stable error content and sanitizes caught callback errors; RCD-06 validates closed policy and projects fields explicitly. The reason digest is acceptable because official DD section 10 now requires its root call ID to link the durable native Session arguments retaining the actual reason. The read budgets expressly exclude GAT provisional submission. Reference revisions are bounded nonempty opaque strings; the candidate now accepts the nonnumeric `approved-v1` fixture.

The exact delta passes remaining packet-validation bytes into the bounded host reader and reserves worst-case evidence/rationale allocation synchronously before asynchronous reads.
