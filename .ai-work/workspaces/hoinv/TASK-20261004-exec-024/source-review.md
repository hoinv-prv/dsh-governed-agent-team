## Findings

### SR-01 — high: caller config can change across the first await

`installExecutionBindings` validates the caller's limit caps, then awaits `realpath(config.workspace)`, and only afterwards clones/freezes `config.limits` and `config.members`. Mutation during that await can therefore pass a validated limit and later retain a different, unvalidated hard limit. This violates DD section 10's immutable normalized configuration and fixed ceiling contract.

This reviewer reproduced the issue without writes/provider activity using the emitted function and a structural context with inert event registration: call `installExecutionBindings` with `maxReadCalls: 8`, immediately change the same object to `1_000_000_000`, then await. Installation succeeded and installed its event hooks. This is a focused setup-race reproduction; it is not a real Loader qualification.

Correction: detach and validate the complete configuration synchronously before the first await; canonicalize the copied workspace and construct the effective immutable configuration only from that detached value. Add a real apply/normalization fixture mutating the caller-owned input while normalization is pending and prove the original accepted limits/declarations remain authoritative or mutation fails closed. Preserve design-before-code order for any clarification.

### SR-02 — medium: ordinary read executor omits exact caller checks

The ordinary memory definition's `execute(args, exec)` checks the captured binding and selected ID but does not reject `exec.agent !== capturedAgent` or nested execution before calling the provider. Its finalizer checks foreign Agent only after the read. The reviewer executor already performs both checks. Registry visibility/guards cover normal routing, but the public/retained definition executor itself does not implement the promised exact caller boundary.

Correction: enforce exact Agent identity and top-level execution at the start of the ordinary executor, before attempt/provider work. Qualify a retained definition invocation with a foreign Agent and nested invocation with zero provider reads. This narrows executor authority and changes no supported normal call.

### SR-03 — high: reviewer authorization is not checked on model requests

The Binding `agent/request` listener revalidates only GAT/task/WK binding authority. The optional reviewer installer checks candidate/port/trusted `assertCurrent` at creation, tool execution and content finalization, but registers no reviewer-specific request guard. If its trusted port is replaced/withdrawn or its candidate authorization is revoked between requests, the next model request can still dispatch with previously logged evidence until another review tool is called. Stale reviewer authorization must not be confused with still-current ordinary binding identity.

Correction: add an exact-Agent-owned reviewer `agent/request` waterfall that checks the same reviewer current/candidate/port authority before and after downstream await, and retains denial after cutoff. Qualify actual retry/next-request revocation with no additional transport. For revocation during a later downstream LLM preparation await, a synchronous polling callback alone cannot supply notification: the trusted host workflow must synchronously cancel the exact Agent as part of revoke/cutoff, or an existing public notification seam must be qualified. Do not claim that pre-request polling closes that separate interval; do not patch Core.
