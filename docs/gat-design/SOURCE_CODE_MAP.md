## Maintenance procedure

1. Read the existing official design and affected contracts through the wiki-first workflow.
2. Describe and review the intended DD input/output/ordering/failure change before source implementation, then inspect final source, callers, types and tests for consistency.
3. Refresh the symbol locator and source hash; keep status Current/Standalone/External/Target explicit.
4. Update BD behavior and AD ownership only when the source change affects those layers.
5. Check links, ID coverage, mapped symbols and byte hashes; run behavioral checks when product changes warrant them.
6. Apply wiki registration/refresh through its reviewed plan; no source mapping itself promotes canonical knowledge.
