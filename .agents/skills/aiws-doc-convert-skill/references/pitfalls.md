# Known Pitfalls — aiws-doc-convert-skill (xberg engine)

Lessons already applied to the scripts.

---

### 1. Unicode / long source paths on Windows
xberg (Rust) can fail to open files whose path contains certain unicode or that exceed
the 260-char MAX_PATH. Prefer running from a short working dir; if a path fails, copy the
file to a short ASCII-named temp and convert that. The output always records the original
source path at the top of `source.md`.

### 2. Giant Excel data sheets explode the render
Rendering a 20,000-row sheet to page images produces hundreds of useless pages and times
out. `extract_hybrid.py` treats sheets over `DATA_ROWS` (300) or `DATA_COLS` (60) as data
dumps: it keeps a text sample (first ~80 rows), skips the image render, and writes a ⚠️
warning naming the sheet + pointing to the source. Raise those thresholds if you truly
need every sheet rendered.

### 3. Legacy binary .ppt has no OpenXML parts
python-pptx only reads `.pptx`. For legacy `.ppt`, `extract_pptx.py` catches the failure,
falls back to render-only via PowerPoint COM (which opens `.ppt` fine), and the enhancement
pass reads the slide images for text. The zip media-extraction is also guarded (legacy
`.ppt` is an OLE compound file, not a zip).

### 4. Office routes need Office; degrade gracefully
xlsx/pptx/docx page rendering uses Excel/PowerPoint/Word COM (Windows + MS Office). Handler
imports are lazy, so on a machine without Office only those routes fail (with a clear
message) — text/pdf/image/text-format routes keep working, including on macOS/Linux.

### 5. Mermaid from the enhancement pass is AI-drawn
Diagrams turned into Mermaid are generated by the VLM from the rendered image and can
mis-copy an edge or label. The PNG render is always kept alongside as ground truth — treat
Mermaid as the searchable form, the image as the source of truth.

### 6. Enhancement is opt-in and costs tokens
Phase 1 (extraction) is mechanical and cheap. Phase 2 (summaries + Mermaid) reads each unit
image via the VLM (~5k tokens/image). Always ask before running it; never auto-run on a
large deck/workbook.
